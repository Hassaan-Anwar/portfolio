# Dev.Lair Architecture & Technical Documentation

## 1. Overview
**Dev.Lair** is a highly interactive, tactile web portfolio designed to mimic a vintage, neon-lit record shop. Instead of scrolling through standard text grids, users interact with the developer's work by physically sifting through 3D "Crates" of "Vinyl Records." Each record represents a discrete piece of content (an "About Me" profile, a featured project, or a work experience). 

By leveraging heavy physics and gestural interactions, users can physically tear a record out of a crate and throw it onto the right-hand dashboard to "play" it, bringing the portfolio to life with rich glassmorphism aesthetics and pixel-art elements.

---

## 2. Tech Stack
- **Framework:** Next.js (App Router paradigm) with React.
- **Styling:** Tailwind CSS combined with raw CSS for complex gradients and glassmorphism.
- **Animation & Physics:** `framer-motion` (powers the 3D stacking, elastic dragging, layout transitions, and physics-based gestural controls).
- **State Management:** `zustand` (provides a lightweight, globally accessible store without React Context boilerplate).
- **Icons:** `lucide-react`.

---

## 3. Core Interaction Flow

The interaction model is built entirely around **gestures** rather than traditional clicking. 

1. **Sifting (Drag Left):** When a user grabs the front record of a Crate and drags it to the left (surpassing a `-100px` threshold), dropping it will trigger an array mutation. The front item is cycled to the back of the stack, and the next record visually floats to the front. 
2. **Playing (Drag Right):** When the user drags a record far to the right (surpassing a `200px` threshold—simulating tossing it onto the dashboard) and releases it:
   - The global `zustand` state is instantly updated to reflect this item as the newly active content.
   - The record triggers a sift mechanism to get out of the way for the next item in the Crate.
   - The right-hand dashboard instantly mounts the item's details.
3. **Vinyl Extraction (Hold):** When a user clicks and holds a record within the crate, the outer Crate layout listens to `onTapStart`. It dynamically drops the opacity of the "sleeve" jacket to `0` and isolates the vinyl disc right under the cursor, giving the illusion of sliding the record fully out of its jacket.

## 4. Application Architecture & File Structure

The codebase is contained entirely within the `src/` directory.

### `/src/app/`
- `layout.tsx`: HTML setup and Next.js metadata.
- `page.tsx`: The root mounting point. It imports the heavy UI components dynamically (`ssr: false`) to bypass server hydration mismatches with heavy window-based animations.
- `globals.css`: Contains CSS reset rules, raw keyframe animations (floating cats, twinking stars, spinning vinyl), and global typography imports (Space Grotesk, JetBrains Mono, Press Start 2P). 

### `/src/store/`
- `musicStore.ts`: The central nervous system. Uses `zustand` to track:
  - Which section is currently active (`activeSection`: 'about' | 'projects' | 'bestsellers' | 'experience').
  - The array index of the currently active item, avoiding passing massive object data across components.
  - Global playback state (e.g., `isPlaying`, `muted`).

### `/src/data/`
- `projects.ts` & `experience.ts`: Static arrays containing the content payload (titles, descriptions, tech stacks, theme colors, glowing accents, and designated pixel-art emojis).

### `/src/components/`
The UI is broken down into distinct, heavily isolated React components to prevent massive re-renders:

#### A. The Environment (`PixelRoom.tsx`)
The master layout orchestrator. 
- Maintains a fixed, absolute background of twinking stars and floating cats.
- Uses a sticky top-header (`DEV.LAIR`).
- Implements the **Asymmetric Split Layout**:
   - **Left Pane:** A freely scrolling container holding the stacked Crates.
   - **Right Pane:** A `position: sticky` container permanently housing the `NowPlayingPanel`. As the user scrolls the left library, the right player follows them strictly down the viewport.

#### B. The Library (`Crate.tsx` & `VinylRecord.tsx`)
- **`Crate.tsx`**: A 3D spatial viewport injected with `perspective: 1000px`. It maps through `CrateItem` objects, manipulating `z-index`, `scale`, and `y` offsets based on array index to create physical depth. It is responsible for handling the `drag` physics generated by `framer-motion`.
- **`VinylRecord.tsx`**: The aesthetic unit. Renders the grooved disc (via complex linear/radial CSS gradients) and manages its own hover/press visual behaviors (sliding horizontally on hover).

#### C. The Outputs (`NowPlayingPanel.tsx` & `MusicPlayerFooter.tsx`)
- **`NowPlayingPanel.tsx`**: The main right-side dashboard. It subscribes to `zustand`. When the active ID changes, it gracefully mounts the new project's metadata, long-form descriptions, tech stack chips, and spinning visualizers. It utilizes heavily blurred backgrounds (`backdrop-filter`) to integrate with the environment.
- **`MusicPlayerFooter.tsx`**: An explicit `100vw`, fixed-position footer anchored to the bottom. Designed intentionally like Spotify, it splits into left (small thumbnail art + titles), center (scrubber bar, play/pause toggles), and right (meta actions like GitHub drops or modal triggers).

## 5. CSS & Z-Index Management Reference
Because the application relies heavily on cross-boundary dragging, z-index hierarchy is strictly guarded:
- **`Background / Stars`**: `z-index: 0`
- **`NowPlayingPanel`**: `z-index: 0` (relies on its own container constraints).
- **`Top Header`**: `z-index: 60`
- **`Left Crates Pane`**: `z-index: 50` (Higher than the right dashboard. Crucial: allows dragged records to visually float *over* the dashboard without clipping).
- **`MusicPlayerFooter`**: `z-index: 50` (Sits globally on top of the layout to ensure it is never covered).

## 6. How to Extend
To add new records to a bucket, simply append a new object to the related array (e.g., `PROJECTS` in `projects.ts`).
To add a new entirely separate section (e.g., "Blog Posts"), you would:
1. Define the type interface in `musicStore.ts`.
2. Construct a new `<Crate />` row block in the left pane of `PixelRoom.tsx`.
3. Map the data cleanly into `<VinylRecord />` children.
